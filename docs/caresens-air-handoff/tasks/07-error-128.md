# Task 07: error 128

Setup and conventions: `00-shared-infrastructure.md`. Background:
`../findings.md`, section "Errors 8 and 128".

## Goal

Reproduce the revised-current stage consumed by error 16. Separately,
find an input that sets bit 128 or establish when the bit is unreachable.

## Known

- **Emitted bit.** Bit 128 stayed clear in the recorded tests.
- **Revision stage.** In Task 01's [source experiment](../error-16-evidence.md#the-actual-isf-input),
  `err128_flag` (1562) was set at sequences 1600–1603 with an empty
  calibration list. `err128_revised_value` (1563) held the five-minute
  current from sequence 1599. `err128_normal` (1571) tracks the recovery
  reference. Later type-4 records in the same trace did not request revision.
- **State.**

  | Field | Offset |
  |---|---|
  | `err128_flag_prev[40]` | 48826 |
  | `err128_normal_prev` | 48872 |
  | `err128_revised_value_prev` | 48880 |
  | `err128_CGM_c_noise_revised_value[36]` | 48888 |

  The 36-entry array contains **current** and feeds error 16's 12-tap filter.
  Task 07 owns how to advance the revised-current state. Task 01 owns
  smoothing that input and consuming it in the error-16 conditions.
- **Device block.** There are no `err128_*` parameters. The [task 00
  survey](../device-parameters.md) varied `cal_noise`, `errcode_version`
  and `sensor_version`. Bit 128 stayed clear in every trial.

## Suggested next steps

1. Start with `err16_isf_source.py` and perturb only the normal and previous
   revised values around the onset and recovery. Check both the emitted
   revision flag and the current appended to the history.
2. Compare later type-4 records from the same scenario to isolate what
   enables revision. Check whether the initial gate uses the same
   information as the detector's recovery reference.
3. Investigate bit-128 firing independently. The stored revision is
   reachable even without calibrations.
