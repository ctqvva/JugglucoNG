# Task 07: error 128

Setup and conventions: `00-shared-infrastructure.md`. Background:
`../findings.md`, section "Errors 8 and 128".

## Goal

Find any input that sets bit 128. Then decode it, or show it is unreachable
for the inputs JugglucoNG passes.

## Known

- **Never seen.** It did not fire in any of the experiments listed in task 06.
- **Debug.** `err128_flag` (1562), `err128_revised_value` (1563) and `err128_normal` (1571) were always 0 or NaN. Possibly the detector does not run at all with the default device block, rather than running and not firing.
- **State.**

  | Field | Offset |
  |---|---|
  | `err128_flag_prev[40]` | 48826 |
  | `err128_normal_prev` | 48872 |
  | `err128_revised_value_prev` | 48880 |
  | `err128_CGM_c_noise_revised_value[36]` | 48888 |

  The names suggest a noise-revised glucose ("c_noise") over 36 records, compared with a "normal" value.
- **Device block.** There are no `err128_*` parameters. The [task 00
  survey](../device-parameters.md) varied `cal_noise`, `errcode_version`
  and `sensor_version`. Bit 128 stayed clear in every trial.

## Suggested next steps

1. **Find out whether it runs.** The debug values stay NaN and 0. A
   calibration list in the oracle (`air1_opcal4_cal_list_t`) is one avenue
   since "noise" and "revised" fit calibration noise.
2. **Perturb the state.** Fill `err128_CGM_c_noise_revised_value` and `err128_flag_prev` with values and see whether the debug fields become non-NaN.
3. **If it needs a calibration list,** document that and model it as never firing. JugglucoNG passes no list; test that.
